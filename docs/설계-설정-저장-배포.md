# 설정 · 저장 · 배포 설계

사용자 결정 (2026-10-28)
- 저장: 기존 Supabase 프로젝트 aiapp(서울, 유료 Pro)에 시험지 전용 표와 파일 보관함을 따로 만든다. 다른 앱 표와 섞이지 않게 이름 앞에 exam_ 을 붙인다.
- 비밀번호: 프로그램 전체에 건다(처음 값 3035). 한 번 들어오면 그 기기에서 30일 기억.
- 월별 요금: 프로그램이 AI 를 부를 때마다 사용량과 요금을 직접 기록해 달마다 합친다.
- 순서: 설정·저장·배포를 먼저 하고, 사용자가 설정 화면에 API 키를 넣으면 그 키로 samples 를 읽어 가장 싼 모델을 고른다.

사용자 결정 (2026-10-28, 배포 뒤)
- 다른 사람도 쓰게 한다. 버셀 로그인 막음은 풀고 주소와 비밀번호만으로 들어온다.
- AI 열쇠는 각자 설정에서 자기 것을 넣는다 → 열쇠와 모델은 기기(브라우저)마다 따로 저장하고, 월별 요금도 열쇠별로 보여 준다.
- 보관함은 아직 모두가 함께 본다 (사람마다 나눌지는 사용자에게 물을 것).
- 원장님은 Max 요금제: 매달 들어 있는 API 크레딧을 콘솔 조직에 연결하고 그 조직의 키를 설정에 넣어 쓴다 (구독 로그인으로는 이 프로그램을 돌릴 수 없다).

## 구조

```
브라우저 ──(쿠키)──> Vercel: Next.js 서버 주소 (app/api/*) ──(비밀 머리말)──> Supabase 함수 exam-gateway ──> exam_* 표, exam-files 보관함
   │                    └─> Anthropic API (이 기기의 설정에 저장한 키, 서버에서만 풀어 씀)
   ├──(쿠키)──> Vercel: Python 함수 api/hwpx.py (시험지 JSON → 한글 파일)
   └──(서명 주소)──> Supabase 보관함에 원본·한글 파일을 바로 올리고 내려받음 (Vercel 요청 크기 한도 4.5MB 를 피함)
```

- Vercel 서버는 Supabase 의 모든 앱 자료를 여는 서비스 열쇠를 갖지 않는다. 시험지에 필요한 일만 하는 Supabase 함수 exam-gateway 를 거친다.
  - 함수는 자기 Supabase 서비스 열쇠(함수 기본 환경변수)로 exam_* 표와 exam-files 보관함만 다룬다.
  - Vercel 에는 비밀값을 하나도 두지 않는다 (비밀값을 대화 기록에 남기지 않고 넘길 길이 없어서, 그리고 그편이 안전해서).
  - 함수를 부를 때는 머리말 x-exam-oidc 에 Vercel OIDC 토큰을 보낸다 (Vercel 이 요청마다 이 프로젝트의 서버에 주는 증명, @vercel/oidc 의 getVercelOidcToken).
    함수는 Vercel 공개키(https://oidc.vercel.com/themonsteredu/.well-known/jwks)로 서명을 확인하고,
    발급자 https://oidc.vercel.com/themonsteredu, 대상 https://vercel.com/themonsteredu,
    sub = owner:themonsteredu:project:exam-maker:environment:(production|preview) 일 때만 일한다.
  - 이 작업 환경에서 실제 창구를 시험할 때만: 머리말 x-exam-gateway 에 공유 비밀값 (SHA-256 이 exam_settings.gateway_secret_sha256 과 같아야 함)
  - 로그인 쿠키 서명 열쇠(session.key)와 API 키 암호화 열쇠는 함수 안에서 SUPABASE_SERVICE_ROLE_KEY 로부터 HKDF 로 만든다.
    DB 만 새어 나가도 API 키를 풀 수 없다. Supabase 서비스 열쇠를 바꾸면 모두 다시 로그인하고 API 키를 다시 넣어야 한다.
- 이 작업 환경이나 내 컴퓨터에서 시험할 때는 EXAM_STORE=local 로 Supabase 대신 .data 폴더를 쓴다 (배포에서는 쓰지 않음).

## 표 (public 스키마, RLS 켬, 정책 없음 = 서비스 열쇠로만 접근)

- exam_settings(key text pk, value jsonb, updated_at)
  - password_hash: "scrypt$N$r$p$salt$hash" (처음 3035)
  - session_version: 정수. 비밀번호를 바꾸면 올려서 모든 기기를 다시 로그인하게 한다
  - gateway_secret_sha256: 함수 비밀값의 해시 (읽기·쓰기 금지 키)
  - (anthropic_key, models 는 예전 "프로그램 하나에 키 하나" 자리. 지금은 쓰지 않는다. anthropic_key 는 계속 읽기·쓰기 금지)
- exam_devices(device text pk, created_at, updated_at, key_sealed jsonb, key_last4, key_tag, key_saved_at, models jsonb): 기기마다 AI 설정
  - device: 브라우저 쿠키 exam_device(무작위 32바이트, HttpOnly, 400일. 미들웨어가 처음 온 브라우저에 붙임)의 SHA-256. 쿠키 값은 두지 않는다
  - key_sealed: { v: 2, iv, data } (AES-256-GCM, 창구 함수만 만들고 푼다. apikey.* 동작으로만)
  - key_tag: 열쇠의 SHA-256("exam-key:"+열쇠) 앞 32자리. 같은 열쇠의 요금을 묶는다 (열쇠를 되살릴 수 없다)
  - models: { page, figure } (claude.ts 의 MODELS 가운데)
- exam_usage(id, at, kind 'page'|'figure'|'test', model, input_tokens, output_tokens, cache_write_tokens, cache_read_tokens, usd, doc_id, key_tag)
- exam_documents(id uuid, created_at, updated_at, title, status 'reading'|'done'|'failed', original_files jsonb [{path,name,size,type}], hwpx_path, exam_json jsonb (그림 PNG 는 빼고 저장), cost_usd, note)
- exam_login_attempts(id, at, ok, ip)
- 함수 exam_usage_monthly_by_key(p_key_tag text, months int) → 열쇠 하나의 달마다 횟수·요금 (anon, authenticated 에게는 실행 권한 없음).
  (예전 함수 exam_usage_monthly(months) 는 쓰지 않지만 지우지 않았다: 지우는 문장이 있으면 적용 때 허락 창이 뜬다)
  다른 사람 열쇠의 요금은 보이지 않는다. key_tag 가 없는 예전 기록(시험 기록)은 아무에게도 보이지 않는다

## 파일 보관함 exam-files (비공개)

- originals/<문서 id>/<번호>.<확장자> (예: 1.pdf)
- generated/<문서 id>/<만든 때>.hwpx
- Supabase 보관함은 한글 파일 이름을 받지 않는다 (InvalidKey). 그래서 보관함 안 이름은 영문·숫자로 짓고,
  한글 원래 이름은 문서 기록(original_files[].name, 제목)에 두었다가 내려받기 주소에 붙인다
  (download=<한 번만 인코딩한 이름>. supabase-js 의 download 옵션은 두 번 인코딩해서 이름이 깨진다)
- 올리기: 서버가 서명된 올리기 주소를 만들어 주고 브라우저가 바로 PUT. 내려받기: 서버가 60초짜리 서명 주소를 만들어 준다

## 로그인

- 쿠키 exam_session = "v1.<만료 초>.<session_version>.<HMAC-SHA256(창구가 준 서명 열쇠)>" (HttpOnly, Secure, SameSite=Lax, 30일)
- middleware.ts: /login, /api/auth/login, 글꼴·정적 파일 말고는 쿠키의 모양과 만료만 본다 (화면은 /login 으로, 서버 주소는 401).
  서명 열쇠가 창구에 있어서 미들웨어는 서명을 보지 않는다. 화면 파일에는 자료가 없고, 자료를 주는 서버 주소는 모두 requireSession 으로
  서명과 session_version 까지 본다 (열쇠 10분, 판 60초 캐시). 가짜 쿠키로는 화면 틀만 열리고 자료는 401 인 것을 확인함
- 로그인 실패: 같은 IP 15분에 10번, 전체 15분에 50번, 전체 24시간에 200번 틀리면 막는다
  (DB 함수 exam_login_begin: 시도를 한 줄로 세워 먼저 "틀림" 으로 적고 확인, 맞으면 ok 로 바꾼다.
  동시에 20번 보내도 10번만 허락되는 것을 확인함. 비밀번호 바꾸기의 "지금 비밀번호" 확인도 같은 제한)
- Python 함수도 같은 쿠키 서명과 만료를 직접 확인한다 (서명 열쇠는 요청 머리말 x-vercel-oidc-token 으로 창구에서 받아 10분 캐시)

## 서버 주소 (Next.js app/api)

| 주소 | 하는 일 |
|---|---|
| POST /api/auth/login | 비밀번호 확인, 쿠키 |
| POST /api/auth/logout | 쿠키 지우기 |
| GET /api/settings | 이 기기의 키 저장 여부(끝 4자리만), 이 기기의 모델, 이 열쇠의 월별 요금, 고를 수 있는 모델과 값 |
| POST /api/settings/api-key, DELETE | 키 확인(Anthropic 모델 목록 조회, 요금 없음) 뒤 이 기기에 암호화해 저장 / 지우기 |
| POST /api/settings/models | 이 기기의 쪽 읽기·그림 읽기 모델 |
| POST /api/settings/password | 비밀번호 바꾸기 (지금 비밀번호 확인, session_version 올림) |
| POST /api/read/page, /api/read/figure | AI 읽기 (이 기기의 키·모델. 키가 없으면 바로 거절하고 서버 환경변수 키로 넘어가지 않음. 사용량은 열쇠별로 기록, docId 가 있으면 문서에 묶음) |
| GET/POST /api/documents, GET/PATCH/DELETE /api/documents/[id] | 보관함 문서 |
| POST /api/files/upload-url, /api/files/download-url | 서명 주소 |
| POST /api/hwpx (Python) | 시험지 JSON(그림 PNG 포함) → 한글 파일 |

## 화면

- / 시험지 만들기: 제목, PDF·사진 고르기 → 원본 보관 → 쪽마다 그림으로 바꿔(pdf.js) 쪽 읽기 → 그림 잘라 읽기 → 합치기 → 그림 PNG → 한글 파일 → 내려받기와 보관
- /archive 보관함: 제목, 날짜, 문항 수, 요금, 원본·한글 파일 내려받기, 지우기
- /settings 설정: 이 기기의 API 키·모델, 이 열쇠의 월별 요금, 비밀번호 바꾸기(모두 함께 쓰는 비밀번호), 로그아웃
- /login

## Vercel 환경변수

- 비밀값 없음. (선택) EXAM_GATEWAY_URL: 없으면 코드의 기본 주소
- 이 작업 환경 시험용으로만: APP_SECRET (EXAM_STORE=local 일 때 쿠키 서명·키 암호화), EXAM_GATEWAY_SECRET (실제 창구 시험)
- (선택) ANTHROPIC_MODEL_PAGE / ANTHROPIC_MODEL_FIGURE: 기기 설정에 모델이 없을 때의 기본값
